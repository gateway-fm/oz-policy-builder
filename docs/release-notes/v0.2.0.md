# v0.2.0 release notes (draft)

Not yet released. Entries are added as changes land, in the commit that makes them.

## Breaking changes

- **An uncapped grant needs an explicit acknowledgement.** `UserDecisions` gains
  `unlimited_calls_acknowledged`, mirroring `no_expiry_acknowledged`; an absent field reads as
  `false`. A decisions document with `max_calls: null` (or no `max_calls`) and no
  acknowledgement is now refused with an `E_NEEDS_DECISION` finding, where it used to
  synthesize a grant with no call cap. Set `unlimited_calls_acknowledged: true` only after the
  user explicitly accepts unlimited calls. A positive `max_calls` together with the
  acknowledgement is refused as contradictory, with an `E_INVALID_DECISION` finding. Decisions
  documents that set `max_calls`, including every one this repository ships, are unaffected.
- **Contradictory lifetime decisions are refused.** A `valid_until_ledger` together with
  `no_expiry_acknowledged: true` used to synthesize the expiring grant and ignore the
  acknowledgement; it is now refused with an `E_INVALID_DECISION` finding, as is the call-cap
  pair above, so the user is asked which one they meant.

A refused synthesis reports every finding in `details`; its top-level code is the first
finding's (`E_INVALID_DECISION` findings report `E_SPEC_INVALID` there), so read `details`.
